Overview

The Cartly API is a public REST API backed by a FastAPI server running on Railway in Singapore. No authentication is required. All search results are cached for 6 hours — repeat queries within that window return instantly from the database without re-scraping.

The search endpoint streams results progressively using Server-Sent Events (SSE). This means results from faster stores appear immediately while slower scrapers are still running. You should consume the stream rather than waiting for the connection to close.

Singapore only. The Giant scraper uses geo-restricted DNS and only returns results when the server is on a Singapore ISP. All other stores work globally.

GET /api/search

Search for a grocery item across all stores. Returns a Server-Sent Events stream.

GET /api/search Live price search · SSE stream ▼
Query parameters
ParameterTypeDescription
q string required The search query, e.g. milo, meiji milk, royal umbrella rice
fresh boolean optional Pass 1 or true to bypass the 6-hour cache and force a full re-scrape. Default: false
This endpoint returns Server-Sent Events, not JSON. Use EventSource in the browser or an SSE-capable HTTP client. The connection stays open until a done event is emitted.
Request
curl -N "https://cartly-production-9eb2.up.railway.app/api/search?q=milo"
SSE event — cached results (emitted immediately)
data: {
  "type":   "results",
  "source": "cache",
  "results": [
    {
      "product_id":     42,
      "name":          "Milo Activ-Go Chocolate Malt Drink",
      "brand":         "Milo",
      "unit":          "1kg",
      "image":         "https://...",
      "store_key":     "ntuc",
      "store_name":    "NTUC FairPrice",
      "store_color":   "#e8231a",
      "price":         10.95,
      "original_price":13.50,
      "promo":         "Member's price",
      "scraped_at":    "2026-05-16T10:30:00Z"
    }
  ]
}
SSE event — live scrape result (emitted as each store finishes)
data: { "type": "results", "source": "live", "results": [ ... ] }
SSE event — stream complete
data: { "type": "done" }
Browser example
const es = new EventSource('/api/search?q=milo');

es.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type === 'results') renderResults(msg.results);
  if (msg.type === 'done')    es.close();
};

Server-Sent Events

The /api/search endpoint uses SSE to stream results progressively. All 5 scrapers run in parallel — results from faster stores appear within seconds while slower scrapers continue running.

Event sequence for a fresh (uncached) query:

  • Immediately — a cache results event with any prices already in the database
  • As each scraper finishes — a live results event with the full updated result set
  • When all scrapers finish — a done event; close the connection

For a cached query (scraped within the last 6 hours), only a single cache event and a done event are emitted — no scraping occurs.

Rate limits & fair use

There are no hard rate limits. Each search triggers up to 5 Playwright browser instances on a shared server — please avoid bulk automated querying. The cache means repeating the same query within 6 hours is free (database-only, no scraping).
